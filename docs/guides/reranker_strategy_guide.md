# RAG Reranker & Response Strategy Guide

이 문서는 RAG 시스템의 **답변 정밀도(Precision)**와 **풍부함(Richness)** 사이의 균형을 조절하기 위한 전략과 설정 가이드를 제공합니다.

---

## 1. 주요 조절 요소 (Leverage Points)

RAG의 답변 품질은 크게 두 가지 요소로 결정됩니다.

### A. Reranker Threshold (임계값)
- **위치**: `app/infrastructure/rag/nodes.py` 내 `min_relevance_score`
- **역할**: 검색된 청크 중 어떤 수준 이상의 정보만 답변 생성기(Generator)에게 넘길지 결정합니다.
- **수치 설정 가이드**:
    - **High (5~7)**: 질문에 대한 직접적인 증거만 허용. 할루시네이션(Hallucination) 억제에 유리하지만, 답변이 매우 건조하거나 '정보 없음' 답변이 잦아질 수 있음.
    - **Low (2~4)**: 질문과 관련된 배경 지식이나 주변 정보도 수용. 답변이 풍부해지고 사용자 친화적이지만, 관련성이 낮은 노이즈가 포함될 확률이 높아짐.

### B. Answer Generation Strategy (프롬프트 규칙)
- **위치**: `app/infrastructure/rag/nodes.py` 내 `generate_answer` 노드 프롬프트
- **전략의 종류**:
    - **Strict Context (고정 관념)**: "문맥에 없으면 절대 답하지 마라." (보안이나 규정 준수가 중요한 경우)
    - **Helpful Completeness (친절한 가이드)**: "문맥을 최우선하되, 부족한 부분은 상식으로 채워라." (일반 상담이나 정보 제공 시 유리)

---

## 2. 'Never Gonna Give You Up' 사례 분석

| 요소 | 이전 상태 (Strict) | 현재 상태 (Helpful) |
| :--- | :--- | :--- |
| **Threshold** | 5 (직접 증거 위주) | 3 (배경 정보 포함) |
| **Reranker** | 직접 답변만的高점 부여 | 가수, 연도 등 인근 정보에도 가점 |
| **Generator** | 문맥 내 가사만 반복 | 가사 소스 인용 + 가수(Rick Astley) 정보 보강 |
| **결과** | "가사 노래는 이 노래입니다." (sparse) | "이 노래는 릭 애슬리의 곡이며, 가사는..." (rich) |

---

## 3. 상황별 권장 설정 (Recipes)

### 🎯 Case 1: 전문 기술 문서 / 사내 규정 조회
- **목적**: 정확한 사실 전달 (오답 방지 최우선)
- **Reranker Threshold**: `5` 이상
- **전략**: `CONTEXT IS ABSOLUTE` (상식 개입 최소화)
- **장점**: 답변의 신뢰도가 매우 높음.
- **단점**: 질문이 조금만 어긋나도 답변을 못함.

### 🌟 Case 2: 일반 대화형 비서 / 도메인 보조
- **목적**: 사용자 만족도 및 서비스 품질 (친절한 답변)
- **Reranker Threshold**: `3` 내외
- **전략**: `HELPFUL COMPLETENESS` (상식 활용 권장)
- **장점**: 답변이 자연스럽고 추가 질문 없이도 유용한 정보를 한 번에 제공.
- **단점**: 아주 간혹 문맥과 상관없는 상식이 섞일 수 있음.

## 4. 운영 가이드
- **모니터링**: `Reasoning Log`를 통해 리랭킹에서 어떤 청크가 탈락했는지 정기적으로 검토하세요.
- **튜닝**: 특정 질문에서 답변이 너무 부족하다면 **수치(Threshold)**를 먼저 낮춰보시고, 그래도 답변 스타일이 마음에 들지 않는다면 **프롬프트 전략**을 수정하세요.
