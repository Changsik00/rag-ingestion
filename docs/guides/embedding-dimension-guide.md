# Embedding Dimension Management Guide

본 문서는 RAG 시스템에서 ChromaDB와 임베딩 모델 간의 차원(Dimension) 일관성을 관리하는 전략을 설명합니다.

## 핵심 개념: 차원 일관성 (Dimensionality Consistency)

RAG 시스템의 검색 품질은 사용자의 질문(Query)과 저장된 데이터(Document) 간의 **수학적 유사도**에 의존합니다. 이 과정에서 가장 빈번하게 발생하는 기술적 장애는 임베딩 차원의 불일치입니다.

### 1. 왜 차원 고정이 중요한가?
- **계산 불가:** 벡터 데이터베이스(ChromaDB 등)는 컬렉션 생성 시 고정된 차원을 가집니다. 질문의 차원이 이와 다르면 수학적 연산(Dot Product 등)이 불가능하여 에러가 발생합니다.
- **모델 업데이트 대응:** Gemini 같은 클라우드 기반 모델은 성능 향상을 위해 기본 출력 차원을 변경할 수 있습니다 (예: 768 -> 3072). 코드에서 이를 명시적으로 제어하지 않으면, 어느 날 갑자기 검색이 중단되거나 품질이 급락할 수 있습니다.

### 2. 하이브리드 검색에서의 영향
우리 시스템은 **Vector Search(Chroma)**와 **Graph Search(Neo4j)**를 결합합니다.
- 만약 Vector Search가 차원 문제로 엉뚱한 결과를 반환하면, 그 결과에 연결된 Neo4j의 그래프 맥락까지 모두 오염되어 최종 답변의 신뢰도가 상실됩니다.

## 운영 매뉴얼

### 설정 관리 (.env)
차원 값은 코드에 하드코딩하지 않고 환경 변수로 관리하여 유연성을 확보합니다.

```env
# Gemini 임베딩 모델 및 차원 설정
GEMINI_EMBEDDING_MODEL_NAME=gemini-embedding-001
GEMINI_EMBEDDING_DIMENSIONALITY=3072
```

### 모델 변경 시 주의사항
임베딩 모델을 변경하거나 차원 값을 수정할 경우 다음 절차를 반드시 따라야 합니다:

1.  **Chroma 초기화:** 기존 컬렉션은 이전 차원/모델에 종속되어 있으므로 삭제(Delete)해야 합니다.
2.  **전체 재수집 (Re-ingestion):** 모든 원본 데이터를 새 모델/차원으로 다시 임베딩하여 저장해야 합니다. 
    > [!WARNING]
    > 차원만 맞춘다고 데이터가 호환되는 것이 아닙니다. 동일한 모델 버전을 사용해야 유사도 계산이 정상적으로 수행됩니다.

## 현재 설정 상태
- **모델:** `gemini-embedding-001`
- **고정 차원:** `3072` (고정밀 RAG를 위한 Gemini Pro 표준 규격)
